# Fixed model-tool catalog

Operator owns the schemas, descriptions and provider projections generated by
`scripts/generate_tool_catalog.py`. Go `ModelTools` and Python `model_tools` MUST
produce identical declarations for the same codec and sorted admitted operations.
The runtime MUST validate every argument against the authoritative schema before
sending it. Declarations grant no authority.

## Ordinary workflow

Use `attempt_execute` with `operation_id` and direct `input`, then read returned
permitted observations with `observation_read`, then use `finish`. See
[SIMPLE_CAMPAIGN_CONTRACT.md](SIMPLE_CAMPAIGN_CONTRACT.md) for exact fields, defaults,
limits, reference categories and finalization semantics. No model-supplied request
IDs, attempt indices, thread/generation counters, descriptors or bindings are
accepted. The host supplies all of them. Artifact publication is optional for
large/reusable input or large assessment drafts.

| Tool | Meaning |
|---|---|
| `attempt_execute` | Invoke a permitted target operation with direct input or a committed payload/carrier receipt. Optional setup, scenario and verified parent receipt. |
| `observation_read` | Read permitted bytes using the returned execution receipt and observation entry ID. |
| `finish` | Submit an honest minimal assessment, a committed assessment-artifact receipt, or an explicit unavailable reason. Acceptance closes admission; cleanup remains pending. |
| `artifact_publish` | Publish bounded bytes for size, reuse or advanced workflows; returns an artifact receipt. It is not an execution or historical-record receipt. |
| `reference_read` | Read a verified campaign reference handle; never a filesystem path. |
| `record_append` | Optional hypothesis, progress, lineage or coverage history. It does not establish objective truth. |
| `injection_delete` | Remove a retained injection using its executed-attempt receipt and action ID. |
| `snapshot_request`, `snapshot_list`, `snapshot_inspect`, `restore_request` | Optional target state management with existing quota, lineage, closure and batch-skipping rules. |

Harness operating guidance MUST explain direct input, exact returned handles,
receipt categories, evidence reads, rejected submissions and minimal honest finish.
It MUST NOT instruct a model to manufacture missing fields or increase limits to
compensate for invalid calls. Expose advanced capabilities according to effective
target capabilities, not merely the current scenario's wording.

## Provider projection and validation

OpenAI function parameters MUST have an object root without root
oneOf/anyOf/allOf/enum/const/not, including with strict=false. Reviewed projections
retain field schemas and describe cross-field constraints; runtime validation
MUST enforce those constraints. Repeated arbitrary-JSON selector structures MAY
be compacted in provider declarations; the full selector schema and runtime limits
remain authoritative. All supported codecs MUST accept their generated declarations
and validate the same runtime arguments. Strict mode is not an authorization check.

Local errors MUST identify the tool/call, safe field path, rule, correction, whether
execution occurred and whether resubmission is safe. Duplicate JSON keys MUST be
rejected before decoding discards them. Use engine.diagnostic_report for retained
Harness-local errors/stopping facts. It is not a model-facing tool. Internal model
broker, upload chunks and host bookkeeping MUST NOT become model tools.

On successful restore, adopt the replacement binding and skip all remaining calls
in that model response with correlated not-executed results. On accepted finish,
no later tool may execute. Do not replay pending/unknown operations.

Shared model-tools and simple-workflow fixtures MUST pass in Go and Python. Test
provider declaration validity separately from stricter runtime acceptance.
