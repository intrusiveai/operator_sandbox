# Fixed model-tool catalog

Operator owns the schemas, descriptions and provider projections generated by
`scripts/generate_tool_catalog.py`. Go and Python produce identical declarations
for the same codec and admitted operations/surfaces. Declarations grant no authority.
The [shared normalization API](MODEL_TOOL_NORMALIZATION.md) defines translation,
typed handle data, defaults, diagnostics and the unchanged host checks.

## Ordinary workflow

```json
{"origin":"scenario","scenario_id":"configuration","operation_id":"invoke","json":{"prompt":"Reply QA_CONFIG_OK."}}
```

Call `attempt_execute`, inspect its returned observation with
`observation_read({"observation":"<returned handle>"})`, then `finish`:

```json
{"finish_reason":"objectives-addressed","summary":"The marker was observed.","objectives":[{"objective_id":"configuration","outcome":"supported","summary":"Observed QA_CONFIG_OK.","observations":["<inspected handle>"]}]}
```

There is no `input` or `assessment` wrapper in model arguments. Small inputs do
not require publication. Models MUST NOT invent hashes, receipts, descriptors,
IDs or counters. Host messages retain their canonical input and assessment shapes.

| Tool | Model arguments |
| --- | --- |
| attempt_execute | Required origin, operation_id and exactly one json/text/base64/artifact. Scenario origin requires scenario_id; exploratory forbids it. Optional media_type, parent, caller_principal_id, rationale, observations, setup, injection, retain_injections, strategy_provenance_ref, technique_refs. |
| observation_read | observation; optional offset and max_bytes. |
| finish | finish_reason and exactly one inline summary/objectives with optional status/hypotheses/claims/coverage/uncertainties/records, artifact, or unavailable_reason. |
| artifact_publish | purpose, media_type and exactly one json/text/base64. |
| reference_read | reference; optional offset and max_bytes. |
| injection_delete | injection. |
| record_append | kind and flattened hypothesis/progress/lineage/coverage fields from the generated schema. |
| snapshot_request | Optional label and description; empty object is valid. |
| snapshot_list | Optional session, offset and limit; empty object is valid. |
| snapshot_inspect, restore_request | snapshot. |

JSON media type is application/json; text defaults to text/plain; base64 requires
media_type. Artifact handles forbid a media override. Choices use field presence,
so JSON null is valid content. Omitted observations means all permitted feedback;
a supplied list must be nonempty. Omitted setup means none. Setup items carry
surface/mode/scope/selector/placement directly. Nonempty setup requires injection;
injection and retention require nonempty setup. Omitted retention means false.

Models cite typed handles returned by tools or verified references. Observation
handles are distinct from execution, artifact, historical record, hypothesis,
input/reference, injection, checkpoint and session handles. Inspect evidence before
claiming observed content; cite exact inspected ranges for partial reads. Rejected
submissions have no execution handle. Unavailable evidence supports gaps, not
positive claims. Execution success alone does not establish objective achievement.

Optional assessment collections are empty by default. Local labels permit forward
hypothesis/uncertainty references without preregistration. Normalization generates
IDs and derives execution receipt lists from selected observations. Historical
records remain optional. A progress assessment requires interpretation, confidence,
assurance and assessment_summary together; gaps is only valid with that group.

## Provider declarations and runtime validation

All five codecs use concise closed object declarations. Root combinators are
omitted for OpenAI compatibility, including strict=false. Exact mutually exclusive
content/finish choices and record-kind constraints remain enforced by shared
runtime validation. Compact JSON declarations retain the same runtime size, depth,
selector and placement checks. Strict mode is not a resource-authorization check.

Only admitted injection branches are declared, preserving all five supported
surfaces when applicable. Scenario prose does not hide legitimate capabilities.
Argument validation rejects unknown/obsolete fields, duplicate keys and invalid
supplied values rather than silently repairing them. Runtime errors identify the
rule, field, correction and whether execution occurred. Use existing internal
`engine.diagnostic_report` for durable local errors and selection evidence.

On successful restore, adopt the binding and skip remaining calls in that model
response. On accepted finish, no later tool may execute. Do not replay unknown
operations. Finish acceptance, assessment retention, verified Harness exit and
completed cleanup are distinct results.


## Pagination and finish corrections

For a partial read, use the returned `continuation.arguments` verbatim to fetch
another page, and use `citation` to cite the bytes already inspected. For example:

```json
{"readable_observation":"observation-7","citation":"observation-7-range-0-4096","continuation":{"tool":"observation_read","arguments":{"observation":"observation-7","offset":4096,"max_bytes":4096}}}
```

The next call reads `observation-7` at offset 4096. An objective may cite
`observation-7-range-0-4096`; it may not cite unread whole-observation bytes.
These example names represent returned handles, never invented ones.

Required inline finish fields are `finish_reason`, `summary`, `objectives`.
Objective items require `objective_id`, `outcome`, `summary`. Optional structures
can be omitted. If needed, uncertainties are objects, for example:

```json
{"uncertainties":[{"kind":"evidence-gap","description":"Only part of the response was inspected."}]}
```

Uncertainty kind is one of `unresolved-effects`, `unavailable-feedback`,
`truncated-feedback`, `unread-input`, `summarized-input`, `omitted-range`,
`coverage-limit`, `evidence-gap`. Objective outcomes are `supported`, `inconclusive`,
`not-observed`, `not-tested`. `attempts` accepts execution handles, `observations`
accepts inspected citation handles inside assessment items, and `records` accepts
only accepted historical record handles. There is no top-level `observations`.
`tool-guide:finish` exposes the complete enum lists and working examples.
Correct an invalid finish with a new call without invoking the target again.

## Actionable corrections

Follow [the correction rules](../docs/TOOL_CORRECTIONS.md). Field descriptions and
`tool-guide:<name>` distinguish resource categories and local assessment labels.
A schema rejection carries the exact installed constraint reference so Operator
can retain safe, specific corrections without trusting submitted prose. Preserve
that reference and the model-facing path through normalization and wrapping.
Never repair assertions automatically or replay completed effects during recovery.
